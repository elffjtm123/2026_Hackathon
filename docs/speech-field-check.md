# 발화 개선 확인 (S1/S2)

범위: localhost 단일 사용자, 실제 Qwen3-ASR-0.6B. CPU 대응·대본 정렬·전체 리포트/저장 재설계는 보류.

## 변경

- PCM을 20ms WebRTC VAD(mode 2)로 관찰하고 연속 음성 100ms에서 발화를 시작한다.
- 시작 전 200ms·종료 후 100ms 여유 구간, 무음 500ms에서 확정, 최대 8초에서 비중첩 분할한다.
- 패킷 큐(32)와 확정 발화 큐(2)를 분리했다. 한도 초과는 오류·미완료로 표시한다.
- 종료 시 마지막 부분 프레임과 확정 발화를 처리한다. 무음·시작 기준 미만 잡음은 STT에 전달하지 않는다.
- 확정 발화 ID로 재전송만 중복 제거한다. 같은 문장을 실제로 다시 말하면 둘 다 보존한다.
- 한국어 음절 수/실제 VAD 발화 시간 합으로 속도를 계산한다. 영문·숫자는 한국어 음절 수에서 제외한다.
- 최근 확정 발화 기준으로 2초 이상 음성·10음절 이상일 때 속도를 표시한다. 최근 창은 종료 시각이 10초 이내인 발화 전체를 사용하며 단어별 정확한 10초 분할은 아니다.
- 기준은 140 미만 느림 / 360 초과 빠름이며 검증된 평가 척도가 아닌 기존 UI의 초기 설정이다.
- 속도·습관어·반복어 분석은 서버 내부의 한 구현을 사용한다. 반복어는 습관어에 더하지 않고 말더듬으로 진단하지 않는다.
- 화면은 서버 전사 스냅샷·누적 습관어·속도 판정·경고 구간 수를 사용한다. 습관어는 STT 텍스트에 남은 후보만 검출한다.
- 지연된 전사는 보존하되 오래된 속도 근거는 현재 시간 기준으로 만료한다. 무음 대기 뒤에 이전 경고가 다시 표시되지 않도록 이벤트 순서를 유지한다.

## 실제 모델 확인

사용자 녹음 대신 macOS 한국어 합성 음성을 사용했다. Qwen MPS와 MediaPipe/MobileGaze 준비 상태를 확인했다.

- 합성 무음 2초: 수신 확인 10회, 전사 없음, 오류 없음, 정상 완료.
- 합성 한국어 음성 15.026초: 동일 문장 2회 + 종료 직전 ‘네’, 수신 확인 76회, 오류 없음, 정상 완료.
- 동일 문장은 u1/u2로 모두 보존됐고 마지막 ‘네.’는 u3으로 보존됐다. 마지막 발화의 VAD 음성 구간은 260ms였다.
- ‘음’은 누적 2회, 음절 수 67, VAD 발화 시간 11,460ms로 집계됐다.
- 결과는 처리 경로 확인이며 자연 발화·잡음·개인별 STT 정확도의 정량 평가가 아니다.
- 자동 검증: Python 122개·Node 29개 통과, 정적 검사·타입 검사·빌드 통과. 비동기 결과 지연·상태 저장 지연·패킷 내 종료 발화를 별도 회귀 검증했다.

## 사용자가 확인할 항목

1. http://localhost:9000 새로고침 후 정면 보정을 완료한다.
2. 약 5초 말하지 않았을 때 새 전사가 만들어지지 않는지 확인한다.
3. ‘음, 저는 백엔드 개발자입니다’를 잠깐 쉬며 두 번 말한다. 종료 결과에 두 문장과 누적 습관어를 확인한다.
4. 마지막에 ‘네’라고 말하고 바로 종료한다. 받아쓰기 마지막 답변을 확인한다.
5. 작은 목소리·주변 잡음·자연스러운 문장 내 쉼에서 누락 또는 지나친 분할이 있는지 기록한다.

VAD·RMS는 물리 입력에 대한 초기값이다. 실제 잡음·작은 목소리에서는 현장 확인 후 조정한다. 8초 상한은 단어를 자를 수 있으며 STT가 습관어를 생략하면 후처리로 복원하지 않는다. S3~S5의 대본/리포트/DB 정책과 추가 확인 항목은 realtime-field-check.md를 따른다.
