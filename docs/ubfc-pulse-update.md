# UBFC 사전학습 모델과 연속 BPM 표시

## 현재 모델

발표 화면의 동일한 video/MediaStream을 사용한다. 기존 음성·시선 기능과 함께
실행하며 별도 카메라를 열지 않는다. 모델은 발표 종료 후 선택한다.

| 모델 ID | 가중치 | 전처리 / ONNX 입력 |
| --- | --- | --- |
| ma_ubfc_tscan (기본) | MA-UBFC_tscan.pth | DiffNormalized + Standardized / 90×6×72×72 |
| ubfc_efficientphys | UBFC-rPPG_EfficientPhys.pth | Standardized / 91×3×72×72 |
| ubfc_tscan | UBFC-rPPG_TSCAN.pth | DiffNormalized + Standardized / 90×6×72×72 |
| ubfc_physformer | UBFC-rPPG_PhysFormer_DiffNormalized.pth | DiffNormalized / 1×3×160×128×128 |
| pure_efficientphys | PURE_EfficientPhys.pth | Standardized / 91×3×72×72 |

공식 저장소: https://github.com/ubicomplab/rPPG-Toolbox
고정 revision: `b7500b848f84ad7f86e277b4612563b69f4f88f9`.
현재 기본 모델은 [Motion Matters](https://motion-matters.github.io/)의 움직임 증강
UBFC 학습 TS-CAN이다. 같은 모델 구조에 다른 사전학습 가중치를 사용하며,
더 잘 동작할 가능성을 비교하는 후보이지 실제 사용자 정확도가 검증된 것은 아니다.
PhysFormer는 공식 설정 patch=4, dim=96, ff_dim=144, heads=4, layers=12,
theta=.7, gra_sharp=2.0을 사용한다. 출력은 모두 DiffNormalized 맥파이다.
코드/가중치 SHA-256을 확인하고 `weights_only=True`, strict load로 변환한다.
첨부된 Downloads의 EfficientPhys 파일과 공식 파일의 SHA-256 일치도 확인했다.
원본 파일은 수정하지 않았다. 학습 데이터셋 전체 다운로드나 재학습은 하지 않았다.

```powershell
# 기존 pulse 의존성이 설치된 환경
.venv/Scripts/python.exe scripts/prepare_ubfc_pulse.py --download
npm run prepare:pulse-assets
```

RAIL 1.1 조건 사본: `public/pulse-licenses/EfficientPhys-RAIL1.1.txt`.
배포 시 가중치·학습 데이터의 이용 조건도 확인해야 한다.

## 갱신 구조

- 신경망 경로에서 눈 사이 거리/화면 너비 <.15, 약간의 눈높이 차이/코 위치를
  근거로 모든 프레임을 차단하던 조건을 제거했다. 실제 얼굴 픽셀 크기·화면 내
  가시 면적을 확인한다. 보통의 각도/움직임은 진단 경고로 표시하고 분석을 계속한다.
  얼굴 없음·다인·실제 해상도 부족·화면 이탈·급격한 위치 전환·나쁜 조명은 차단한다.
- 얼굴 검출 갱신 시 crop 중심/크기를 평활화하고, 테두리에서도 정사각 crop을
  유지한다. 신경망은 밝기를 확인할 영역이 2개 이상일 때 전체 얼굴을 분석한다.
  POS 비교 실험의 기존 엄격한 입력 조건은 별개로 유지한다.

- EfficientPhys/TS-CAN은 약 3초, PhysFormer는 약 5.34초의 겹치는 최신 영상을
  사용한다. 요청 목표 간격 1초, 동시 요청 1개. 처리 중 밀린 요청을 쌓지 않는다.
  실행 사양에 따라 실제 갱신은 더 느릴 수 있다. 실제 간격과 추론 시간을 표시한다.
- 중첩 결과는 원래 촬영 시각에 맞춰 교체한다. 같은 시간을 두 번 누적하지 않으며,
  역순/오래된 출력과 다른 세션의 응답을 제외한다. 최근 최대 20초를 분석한다.
- 입력은 최소 15fps, 유효 프레임 간격 최대 250ms. 실제 촬영 시각을 30Hz로
  보간하나, 이는 촬영되지 않은 정보의 복원이나 실제 30fps 보장을 의미하지 않는다.
- 실제 모델 출력이 6초 이상일 때 45~180 BPM 대역에서 잠정 BPM을 계산한다.
  피크가 >47/<178 BPM, 진폭 >1e-5, 대역 내 피크 에너지 비율 >=0dB일 때만 표시한다.
- 15초 이상, 에너지 비율 >=3dB, 전후반 주파수 차이 <=12 BPM 및 첫 구간과 전체
  차이 <=12 BPM이면 '주기성 양호'이다. 정확도 확률이나 센서 검증 결과가 아니다.
- 표시값은 최근 3개 중앙값 + EMA(alpha=.35)로 평활화하고 원래 BPM도 표시한다.
  품질 판정은 평활화 전 신호로 한다. 일정한 숫자를 만들기 위해 가짜 신호를 넣지 않는다.
- 무효 입력/경계 주파수/약한 신호에는 숫자를 생성하지 않는다. POS나 샘플값으로
  대체하지 않는다. 6.5초 이상 오래된 결과를 현재값으로 표시하지 않는다.
  재시작 횟수와 원인도 표시한다.
- 원시 얼굴 밝기 그래프와 모델 맥파를 구분한다. 첫 추론 완료 전 영상 수집 시간을
  모델 맥파 시간으로 표시하지 않는다. 0회 추론이면 모델 맥파도 0초이다.
- 종료 시 마지막 수치를 '종료 · 마지막 추정값'으로 화면 메모리에 남긴다.
  잠정값 여부를 유지한다. 새 발표·모델 변경·분석 OFF 시 초기화한다.
- 연습 중 신호가 끊기면 최근 실제 산출값을 '이전 추정값 · N초 전 · 현재값 아님'으로
  유지한다. 나이는 실제 영상 결과의 시각에 기반해 증가한다. 새 결과가 들어오면
  즉시 현재값으로 전환한다. 이전 값으로 추정기/평활화기/개인 기준을 갱신하지 않는다.
  이 방식은 숫자의 연속 표시이지 누락 구간의 새로운 맥박 측정이 아니다.
- 종료 숫자는 전체 평균이 아니다. 최근 최대 20초 모델 신호에서 얻은 주파수 기반
  BPM을 최근 3개 중앙값 + EMA로 표시한 마지막 실제 산출값이다.

## 수치로 얻을 수 있는 정보

현재 가능한 것은 추정 BPM, 발표 중 변화, 수동 개인 기준과의 차이, 신호 품질과
측정 가능한 조건의 확인이다. 수동 기준은 검증된 안정 시 맥박이 아니며, 맥박 상승
이유를 긴장으로 단정하지 않는다. 현재 HRV/PRV·스트레스 점수·혈압·산소포화도는
제공하지 않는다. 평활화된 BPM 값의 분산을 HRV로 계산해서는 안 된다.
박동 간 간격과 신호 품질은 별도 검증이 필요하다. 의료 진단·면접 선발 점수로 사용하지 않는다.

후속 평가는 기준 센서와 시간 정렬한 BPM MAE/RMSE, 측정 가능 비율, 첫 값 지연,
갱신 간격으로 구성한다. 학습과 독립된 시험 데이터를 사용하고, 발표 말하기·조명·
피부톤·카메라별로 구분한다. PURE 학습 모델을 UBFC로 평가하는 교차 데이터셋 실험도 가능하다.

근거 자료:

- 촬영 조건·움직임과 HRV 오차: https://pmc.ncbi.nlm.nih.gov/articles/PMC8704576/
- HRVCam (현재 미연결): https://pmc.ncbi.nlm.nih.gov/articles/PMC7874852/

## 로컬 API와 보관

`GET /api/v1/pulse/model?model_id=...`, `POST /api/v1/pulse/infer?model_id=...`.
개발 모드 + loopback + 허용 Origin을 검사한다. 72×72 EP01 최대 2MiB,
128×128 EP02 최대 10MiB, 최대 181장, 업로드 제한 10초. 선택 모델과 맞지 않는
패킷·시각·크기·모델 이름은 거부한다. 요약 모델 실행 중에는 추론하지 않는다.
ORT CPU 2스레드를 별도 스레드로 실행해 이벤트 루프/음성 WebSocket을 막지 않는다.
모델을 바꾸면 이전 ORT 세션을 교체하며 유휴 모델은 30~40초 내 회수한다.
이미지·맥파·BPM을 파일/DB/로그에 저장하거나 외부 인터넷으로 전송하지 않는다.

## 동작 검증 (생리학적 정확도 평가 아님)

- 최신 회귀 검사: 프론트엔드 26개(실제 worker의 작은 얼굴/기울임 통과 포함),
  백엔드 16개 통과. MA-UBFC TS-CAN ONNX 변환 최대 절대 오차 1.24e-6, allclose 통과.
- 공개 얼굴의 작은 입력(약 59×56px, 눈 사이 36px) + 미세 움직임 + 합성 색 변화에서
  실제 MA 모델 API가 반복 호출되고 BPM이 갱신됨을 확인했다. 기존 눈 사이
  거리 기준으로는 차단되던 크기이다. 얼굴 입력을 제거했을 때 '이전값/경과시간'
  표시와 개인 기준 버튼 비활성화도 확인했다. 얼굴을 다시 넣은 뒤 새 모델 결과로
  복귀하고 반복 갱신되는 것까지 확인했다. 실제 사용자 정확도 평가가 아니다.

이하 수치는 최초 UBFC 세 모델 연결 시의 기록이다.

- UBFC 모델의 PyTorch→ONNX 최대 절대 오차: EfficientPhys 8.94e-7,
  TS-CAN 6.26e-7, PhysFormer 1.43e-6. 세 모델 모두 allclose 통과.
- 맥박 API/실제 세 모델/보안·입력·취소 처리 테스트 15개 통과.
- 프론트엔드 대상 테스트 21개와 빌드 통과. 중첩 시간 중복·역순·갭, 잠정값과
  품질 판정, 평활화 시 원래 값 보존 및 신호 손실 처리, 단일 비디오 공유를 포함한다.
- 공개 얼굴 예제 + 합성 72BPM 색 변화에서 실제 모델/API/공유 video/UI를 검사했다.
  사용자 카메라·마이크를 테스트에서 요청하지 않았다. 기준 센서와의 정확도는 미검증이다.
- 이 로컬 개발 PC에서 합성 입력의 UI 갱신은 EfficientPhys/TS-CAN 약 1.0~1.1초,
  PhysFormer 약 1.5초였다. 각 추론은 약 .21/.38/1.13초 수준이었다. 실제 사람의
  발표 정확도나 다른 PC의 지연을 보장하지 않는다. 세 경로 모두 숫자 표시를 확인했다.
- PhysFormer 실행 중 기존 Qwen Q8 공개 음성 WebSocket 전사·발화 속도·종료 결과와
  모델 회수도 통과했다. 이 검사는 gaze_enabled=false이므로 동시 시선 추정 정확도
  검증을 의미하지 않는다. 추가 부하/프레임 누락 시 재수집 조건은 유지된다.
