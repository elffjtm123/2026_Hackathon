# 목소리 전달력 분석

발표 중 수집하는 STT용 음성으로 전달력(delivery)을 측정하고, 세션 종료 리포트에 대본 구간 단위 피드백을 남긴다. 감정 인식이 아니라 "청중이 받는 인상과 다음 행동"으로 번역하는 기능이다.

## 범위

- 서비스는 한국으로 한정한다. 대상은 한국어 발표, 주로 한국어 원어민 화자다. 특징 계산(한글 음절), 임계값 보정, 실험 데이터 모두 한국어 기준으로 한다.
- 1차는 발표 모드만 다룬다. 면접 모드는 대본 구간이 없어서 2차로 미룬다.
- 학습 모델 없이 규칙 기반으로 판정한다. 한국어 발표 음성에 전달력 라벨이 달린 데이터가 없기 때문이다. 오프라인 실험(아래 "실험")은 특징이 사람 평정과 관련이 있는지 확인하는 용도이며, 서비스 판정 로직에는 들어가지 않는다.
- 감정 라벨(긴장, 기쁨 등)은 UI, 코드, 리포트 어디에도 쓰지 않는다. 모듈 이름은 `delivery`, 화면 이름은 "목소리 전달력"이다.
- 발표 중에는 아무것도 표시하지 않는다. 특징을 계산해서 집계만 하고, 종료 리포트에만 보여준다.
- 원본 PCM, 프레임 타임라인, 발화별 원시 특징은 저장하지 않는다. 리포트에는 문장별 집계값, 세션 기준선, 신호 코드만 저장한다.

## 입력

| 원천 | 단위 | 쓰는 값 |
|---|---|---|
| `SpeechSegmenter`의 `observe_frame` | 20ms 프레임 | 시작·끝 ms, RMS, 유성 여부 |
| `SpeechSegment` | 발화(최대 8초) | 16kHz PCM, 신규 필드 `cut_reason`(`endpoint` / `max_length` / `flush`) |
| STT 전사와 `analyze_utterance` | 발화 | 음절 수, 습관어 수, 반복 수 |
| 대본 정렬 | 발화 시점 | `current_sentence_index`, 대본 일치도, `pace_delta_ms` |
| 마이크 트랙 | 세션 | `getSettings().autoGainControl` 실제 적용값 |

- 마이크는 `autoGainControl: false`로 받는다. `echoCancellation`과 `noiseSuppression`은 유지한다. STT 인식률과 `stt_silence_rms_threshold`가 달라지지 않는지 `docs/speech-field-check.md` 절차에 추가해 확인한다.
- `max_length`로 자른 경계는 쉼으로 세지 않는다. 쉼은 발화 경계가 아니라 프레임 타임라인으로 계산한다. 발화 경계에는 앞뒤 여유분(pre-roll 200ms, post-roll 100ms)이 붙고, 500ms보다 짧은 쉼은 발화 안에 묻히기 때문이다.

## 특징 (문장 단위, 9개)

판정 규칙이 쓰지 않는 특징은 수집하지 않는다.

| # | 특징 | 계산 | 쓰는 규칙 |
|---|---|---|---|
| 1 | 유성 시간, 음절 수 | 유성 프레임 합, 한글 글자 수 | 분모, 판정 자격 |
| 2 | 조음 속도 | 음절 ÷ 유성 시간 (분당) | 준비 부족 |
| 3 | 문장 안 쉼 | 250ms 이상 무성 구간의 횟수와 최장 길이 | 끊김, 막힘 |
| 4 | 문장 끝 쉼 | 문장 마지막 유성 프레임부터 다음 문장 첫 유성 프레임까지의 길이 | 쉼 없음 |
| 5 | 비유창 단어 밀도 | (습관어 + 반복) ÷ 유성 시간 (분당) | 준비 부족 |
| 6 | 몰림 이벤트 | 유성 10초 창 안에 습관어·반복 3회 이상. 시각과 문장 번호 | 막힘 |
| 7 | PVQ | 유성 프레임 F0(Hz)의 표준편차 ÷ 평균 | 단조로움 |
| 8 | 음량 중앙값 | 유성 프레임 RMS의 dBFS 중앙값 | 에너지 낮음 |
| 9 | 대본 일치도, `pace_delta_ms` | 기존 값을 문장에 연결 | 막힘 |

- 발화 속도(쉼 포함)도 문장과 창 특징에 저장한다. 처음에는 조음 속도 × 발성 시간 비율로 계산할 수 있어 따로 저장하지 않기로 했지만, 실험에서 전문가 속도 점수와 맞은 것이 발화 속도였다(Q31).
- 기존 실시간 `syllables_per_minute`와 140/360 기준은 바꾸지 않는다. 이 값은 유성 시간 기준이라 조음 속도에 가깝다.
- 평균 연속 발화 길이(MLR)는 음절 ÷ (문장 안 쉼 + 1)로 거의 결정되고 단어 타임스탬프 없이 근사밖에 할 수 없어서 제외했다. 발성 시간 비율, F0 범위, F0 중앙값, 음량 변동 폭, HNR, jitter, shimmer도 중복되거나, 규칙이 없거나, 행동으로 옮길 수 없어서 제외했다.
- F0는 `praat-parselmouth`(GPLv3+, 사용자 승인)로 발화 PCM에서 추출한다.

## 특징 분류와 감정 분석용 출력 (2026-10-30 실험 이후)

| 특징 | 직접 제공 | 예상 등급 입력 | 감정(각성도) 분석 |
|---|---|---|---|
| 발화 속도와 목표 범위(초당 5.2–5.5음절)의 차이 | ✅ | ✅ | ✅ (발화 속도) |
| 조음 속도 | | | ✅ |
| 비유창 단어 밀도 | ✅ | ✅ | ✅ |
| 분당 쉼 횟수, 최장 쉼 | ✅ | ✅ | ✅ |
| 몰림, 문장 끝 쉼, 대본 일치도 | ✅ | | |
| PVQ | 보류 | | ✅ |
| 음량 중앙값 | | | ✅ (세션 안 상대값) |
| F0 수준 (세션 중앙값 대비 반음) | | | ✅ |
| 스펙트럼 균형 (alpha ratio, Hammarberg index) | | | ✅ |

- 예상 등급은 사용자에게 제공한다. 입력은 위 표의 4개이고, 음량과 PVQ는 넣지 않는다. 모델 학습은 71663 Training 음성을 더 받은 뒤 다음 단계에서 한다(Q34).
- 감정 분석용 특징은 `DeliveryAnalyzer.windows()`가 세션 시계(`audio_origin_ms`) 기준 10초 창 단위로 내보낸다. 창은 겹치지 않고, 창마다 신뢰도(유성 구간 비율)를 함께 낸다. 음성과 심박을 합치는 융합은 이 모듈 밖에서 한다(Q28, Q32).
- F0 추출기는 (시각 ms, Hz) 쌍을 반환한다. 그래야 문장과 창으로 나눌 수 있다(Q33).
- 스펙트럼 균형은 유성 프레임의 PCM으로 numpy FFT를 써서 계산한다. jitter, shimmer, HNR은 브라우저의 노이즈 억제와 코덱 때문에 계속 제외한다(Q30).
- 반복 검출 개선(부분 반복과 다시 말하기)은 `filler_counts`를 바꾸는 일이라 별도 작업으로 한다(Q35).
- 각성 단서 근거:
  - 각성이 높을수록 F0 수준과 변화, 음량, 말 속도, 고주파 에너지가 함께 커진다(Banse & Scherer 1996, Juslin & Laukka 2003 리뷰).
  - eGeMAPS는 이 단서들을 alpha ratio, Hammarberg index 같은 항목으로 표준화했다(Eyben et al. 2016).
  - 두 리뷰의 세부 수치는 원문에서 확인하지 않았다.

## 판정 규칙 (임시값, 실제 마이크 검증 필요)

- 기준선은 세션 전체 문장의 중앙값 하나다. 처음 30초는 긴장이 가장 높은 구간이라 기준선으로 쓰지 않는다.
- 판정 대상은 유성 시간이 3초 이상인 구간뿐이다. 구간은 요약 묶음이 있으면 묶음, 없으면 문장 3개 단위다.

| 신호 코드 | 조건 |
|---|---|
| `monotone` | PVQ가 기준선 대비 −30% 이하 |
| `low_energy` | 음량이 기준선 대비 −6dB 이하 |
| `unprepared` | 조음 속도 +25% 이상과 비유창 단어 밀도 증가가 동시에 나타남 |
| `stuck` | 몰림이 끊김, 속도 급변, 대본 이탈 중 하나 이상과 함께 나타남 |
| `broken_pause` | 문장 안에 2초 이상 쉼 |
| `no_pause` | 문장 끝 쉼이 250ms 미만인 문장이 이어짐 |

- 하이라이트는 좋았던 구간 최대 1개와 고칠 구간 최대 2개다.
- 전체 유성 시간이 60초 미만이거나 AGC가 켜져 있으면 하이라이트와 목표를 만들지 않는다. 상태는 `unavailable`로 두고 사유를 남긴다.
- 습관어는 전사 기반이라 STT가 지운 "어/음"을 놓친다. 그래서 몰림은 단독으로 하이라이트하지 않는다.

## 피드백

- 근거: 자기 자신을 향한 피드백은 수행을 떨어뜨리는 경우가 많다(Kluger & DeNisi 1996). 피드백은 목표, 현재 위치, 다음 행동을 함께 줘야 한다(Hattie & Timperley 2007). 불안을 흥분으로 재해석하면 발표 수행이 나아진다(Brooks 2014).
- 리포트에는 신호 코드와 값만 저장하고, 한국어 문구는 프론트엔드 템플릿에서 만든다.
- 발표 설정에서 구간별 의도 톤(`힘 있게 / 차분하게 / 강조 / 지정 안 함`)을 선택 사항으로 받는다.
- 리포트마다 다음 연습 목표를 하나 저장하고, 같은 사용자의 직전 발표 리포트에 목표가 있으면 달성 여부를 맨 위에 보여준다.
- 높은 각성 신호는 "긴장" 대신 "에너지를 강조로 쓰라"는 식으로 재해석해서 표현한다.

## 모듈 구조

`app/modules/delivery/`에 세션당 하나인 `DeliveryAnalyzer`를 둔다.

```
인터페이스
  observe_frame(start_ms, end_ms, rms, voiced)
  observe_utterance(start_ms, end_ms, pcm, cut_reason, sentence_index, syllables, disfluencies)
  report(intents) -> dict          # delivery_metrics에 그대로 저장
  windows() -> dict                # 10초 창 단위 감정 분석용 특징과 세션 기준선
내부
  쉼 추적        프레임 → 문장 안/끝 쉼
  F0 추출        발화 PCM → 유성 F0 (내부 seam: parselmouth 구현 / 테스트용 가짜)
  문장 누적기    문장별 특징 9개
  규칙           순수 함수 (특징, 기준선) → 신호
  하이라이트     좋음 1개, 고칠 것 2개
```

- 음절 수와 비유창 단어 수는 호출하는 쪽이 넘긴다. 한국어 계산은 기존 `analyze_utterance`를 쓰고, 오프라인 실험에서는 데이터셋 라벨로 계산한 값을 넘길 수 있다.
- `SpeechChangeDetector`(`app/modules/speech/changes.py`)는 이벤트를 쌓기만 하고 읽는 곳이 없다. `DeliveryAnalyzer`가 같은 `observe_frame` 연결 지점을 이어받고, 기존 모듈과 테스트는 정리한다.
- F0 추출은 발화당 수십 ms 수준으로 예상되므로 메인 프로세스에서 `asyncio.to_thread`로 실행한다. 모델 자식 프로세스의 배타 수명주기는 바꾸지 않는다.
- 리포트에 `delivery_metrics` JSON 컬럼을 추가한다(마이그레이션 `0004`). 분석 설정에 `delivery_enabled`(기본 켜짐)를 추가하고 `FeatureToggles`에 노출한다.

## 근거

| 특징 | 근거 | 확인 수준 |
|---|---|---|
| 조음 속도 / 발화 속도 | 낭독 L2 유창성 평정은 전체 시간 기준 속도가 가장 잘 예측했다(r .90–.93). Cucchiarini et al. 2000, JASA 107(2) | 초록 확인 |
| 쉼 | 휴지와 속도 측정이 유창성 지각을 가장 잘 예측하고, 수정(repair) 측정의 기여는 작다. Bosker et al. 2013, Language Testing 30(2) | 초록 확인 |
| 쉼 위치 | 절 내부 휴지가 L1과 L2 차이의 핵심이다. Kahng 2014 | 2차 문헌 |
| 비유창 단어 | 간투사가 청자가 지각하는 확신을 낮춘다. Brennan & Williams 1995 | 초록 확인 |
| PVQ | 정규화한 F0 표준편차가 학생 발표의 생동감 평정과 강하게 상관했다. Hincks 2005, Interspeech. F0 범위 확대가 "좋은 화자" 평정을 가장 강하게 올렸다. Strangert & Gustafson 2008 | 확인 |
| 카리스마와 운율 | Rosenberg & Hirschberg 2009, Niebuhr et al. 2016 | 미확인 / 2차 문헌 |
| 발표 코칭 사례 | 실시간 피드백은 드물고 간단할 때 덜 방해된다(Rhema, Tanveer et al. IUI 2015). 사용자는 타임라인 다시 보기를 가장 유용하게 평가했다(MACH, Hoque et al. UbiComp 2013). ROC Speak(Fung, Jin, Zhao, Hoque, UbiComp 2015) | 서지 확인 |

- 한국어는 어휘 강세가 없고 억양이 구 끝 경계 성조로 실현된다(K-ToBI). 그래서 영어의 문장 끝 상승이나 강세 결과는 그대로 옮기지 않는다.

## 실험

특징이 사람의 전달력·유창성 평정과 관련이 있는지 오프라인에서 확인한다. 서비스 판정은 여전히 규칙 기반이다.

- 1차 데이터: AI Hub 71663 「공적말하기 실습 및 평가 데이터」(언어적 파트만). 한국어 화자가 원고를 준비해 청중 앞에서 2~7분 발표한 mp4 800건이다. 전문가·준전문가·일반인 평가자가 간투어, 휴지, 음성 속도, 반복/수정, 음성 질, 발음을 1–5점으로 매겼고, 총체 등급(A+~F)도 있다. 전사에는 FIL(간투어), REP(반복/수정), PS(5초 이상 휴지), WR 태그가 붙어 있다. 사용자가 직접 신청해서 받는다.
  - 특징과 항목 점수, 총체 등급의 상관을 본다(예: 비유창 밀도 ↔ 간투어 점수, 문장 안 쉼 ↔ 휴지 점수, 조음 속도 ↔ 음성 속도 점수). 평가자 간 일치도를 상한으로 쓴다.
  - 임계값(쉼 길이, 문장 끝 쉼, PVQ 하락폭)을 격자로 바꿔 보며 보정한다. 원고를 강제 정렬하면 문장 끝 쉼도 잴 수 있다.
  - FIL/REP 태그를 정답으로 두고 STT 기반 습관어 집계의 재현율과 정밀도를 잰다.
- 보조 데이터: AI Hub 71557 「뉴스 대본 및 앵커 음성」(Validation만)으로 아나운서의 조음 속도와 PVQ 분포를 얻고, 단조로움 신호가 전문가에게서 얼마나 자주 잘못 켜지는지 본다. Pansori-TEDxKR(OpenSLR 58, CC BY-NC-ND 4.0, 174MB)은 승인을 기다리는 동안 파이프라인 동작 확인용으로 쓴다.
- 이용 조건: AI Hub 데이터는 제3자 제공과 국외 반출이 금지된다. 신청서 활용 목적에 "규칙 기반 분석기의 보정과 평가"를 명시한다.
- 코드: `scripts/`에 특징 추출 스크립트와 실험 스크립트를 둔다. 데이터셋과 결과 파일은 저장소 밖에 둔다.

**창 단위 각성 특징 점검** (재구성 후, 27건에서 10초 창 719개)
- 각성 라벨이 없어서 타당성은 검증하지 못했고, 동작과 공변 구조만 확인했다.
- 같은 화자 안에서 F0 수준과 음량은 함께 움직인다(ρ 0.40). 각성 단서끼리 기대한 결합이다.
- 스펙트럼 균형(alpha ratio, Hammarberg)은 F0, 음량과 거의 무관하고(|ρ| ≤ 0.05) 조음 속도와만 상관한다(0.37–0.45).
  - 발음 내용이나 녹음 특성을 반영할 가능성이 있다.
  - KEMDy로 각성 관련성을 확인하기 전에는 융합에 넣지 않는다.
- 첫 30초를 나머지와 비교하면 F0가 낮고(중앙값 −0.46 반음, p=0.008), 말은 약간 빠르다(p=0.025). "초반에는 각성이 높다"는 가정과 다르다. 그래서 초반 각성을 전제한 피드백 문구는 쓰지 않는다.
- F0 중앙값과 등급의 상관(ρ 0.52)은 성별 교란일 가능성이 커서 사용하지 않는다.

**설계에 주는 시사점 (확정 전)**
- 속도 피드백에는 조음 속도의 상대 변화보다 **쉼을 포함한 발화 속도와 목표 범위의 거리**가 평정과 맞는다. 발화 속도를 저장하지 않기로 한 결정(Q18)을 다시 봐야 한다.
- 반복 검출을 개선해야 한다. 부분 반복과 다시 시작하는 경우를 잡아야 하고, 반복/수정은 등급과 상관이 두 번째로 크다.
- PVQ 단조로움 신호는 근거가 확인되지 않았다. 결과를 피드백에 쓰기 전에 F0 옥타브 오류를 점검하고 세션 안 비교로 다시 검증한다.
