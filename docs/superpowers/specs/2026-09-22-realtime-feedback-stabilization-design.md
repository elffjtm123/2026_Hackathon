# 실시간 피드백 기능 안정화 설계

## 1. 목적

현재 발표·면접 연습 화면에서 보이는 기능을 먼저 신뢰할 수 있는 상태로 만든다. 이번 작업의 우선순위는 새로운 감정 분석이나 LLM 질문 생성이 아니라 다음 네 가지의 실제 동작 보장이다.

1. 세션 종료 직전 음성이 누락되지 않고 최종 받아쓰기에 포함된다.
2. 시선·발화 속도·습관어 피드백이 서로 덮어쓰이지 않는다.
3. Qwen3-ASR 입력 규격과 분석 기준을 일관되게 만들어 결과를 확인할 수 있다.
4. 시선 분석 결과를 관찰 가능한 판정값으로 분리하고, 근거 있는 자연어 피드백을 제공한다.

단일 localhost 사용자와 Apple Silicon MacBook 실행을 기준으로 한다. 다중 사용자 확장, 감정 판정, Laya/Jev, LLM 기반 면접 질문 생성은 이번 범위에서 제외한다.

## 2. 현재 문제

### 2.1 세션 종료 프로토콜

- 프론트엔드는 `session.end`를 보내지만 메시지 변환 함수가 이를 `ping`으로 바꾼다.
- 백엔드 `ClientEvent`가 `session.end`를 허용하지 않는다.
- 프론트엔드는 종료 메시지를 보낸 직후 WebSocket을 닫는다.
- 오디오 훅의 cleanup에서 마지막 청크를 만든 뒤 소켓으로 전송하므로, 이미 닫힌 소켓 때문에 해당 청크가 손실될 수 있다.
- 백엔드 파이프라인은 큐를 비우고 `session.completed`를 내보내는 기능이 있지만 정상 종료 경로에서 사용되지 않는다.

### 2.2 피드백 상태 혼합

- 백엔드는 시선 이벤트에 임의의 정상 발화 값을, 발화 이벤트에 임의의 정면 시선 값을 함께 넣는다.
- 프론트엔드는 모든 모듈의 결과를 `latestFeedback` 하나에 저장한다.
- 따라서 새로운 발화 이벤트가 올 때마다 실제 시선 상태가 `center`로 보이고, 시선 이벤트가 올 때마다 발화 상태가 `normal`로 보인다.

### 2.3 오디오/STT 입력 불일치

- 브라우저는 장치 기본 샘플레이트(대개 48 kHz)로 4초 WAV를 보낸다.
- 문서와 백엔드의 기본 규격은 16 kHz mono이며 설정값 `audio_chunk_ms=750`도 프론트에서 사용되지 않는다.
- 현재 청크 간 연결 규칙이 없어 단어 경계가 잘릴 수 있다.
- 연결 오류 시 자동 Mock 전환이 실제 STT 실패를 숨겨 품질 확인을 어렵게 한다.
- 발화 속도는 청크 전체 길이로 계산되어 무음이 긴 청크에서 실제 말하기 속도보다 느리게 측정될 수 있다.

### 2.4 시선 판정의 불확실성

- 기존 어댑터는 루트의 대형 `video.py`에 강하게 결합되어 있다.
- 학습 모델 없이 8프레임 자동 보정과 규칙 기반 판정을 사용한다.
- 얼굴 미검출도 단순 `away`로 처리하고, 신뢰도는 실제 모델 확률이 아닌 움직임 크기로 합성한다.
- 해상도 320×240, 5 FPS 입력은 눈 영역 추정과 흔들림 판정에 불리하다.
- 시선 이탈 시간은 실제 타임스탬프가 아닌 샘플당 고정 333 ms로 집계된다.

## 3. 채택 설계

### 3.1 전체 흐름

```text
브라우저 카메라/마이크
  ├─ JPEG 640×480, 최대 8 FPS ──> video queue(size=1) ──> gaze adapter
  └─ PCM/WAV 16 kHz mono ───────> audio queue ──────────> Qwen3-ASR
                                                           └─ 발화 속도/습관어

각 모듈 결과 ──> source별 feedback event ──> 프론트 source별 상태
                                         └─ backend aggregator

종료 요청 ──> 마지막 오디오 flush ──> session.end ──> queue drain
          <── session.completed(report) <───────────────┘
```

서버가 `session.completed`를 보내기 전에는 프론트가 소켓을 닫거나 최종 요약을 확정하지 않는다. 종료 제한 시간을 넘기면 프론트가 사용자에게 분석 미완료 상태를 표시하고 연결을 정리한다.

### 3.2 세션 종료 상태 머신

프론트 상태를 `idle | starting | running | stopping | completed | error`로 구분한다.

1. 사용자가 종료를 누르면 `stopping`으로 전환한다.
2. 미디어 캡처를 중지해 더 이상 새 프레임이 생기지 않게 한다.
3. 오디오 수집기가 남은 샘플을 16 kHz WAV로 flush하고 전송 완료를 기다린다.
4. 프론트가 `session.end`를 보낸다.
5. 백엔드는 새 미디어 수신을 막고 큐를 비운 뒤 집계 결과를 만든다.
6. 백엔드가 `session.completed`와 최종 report를 보낸다.
7. 프론트가 report를 저장하고 WebSocket을 닫은 뒤 `completed`로 전환한다.

종료는 중복 호출되어도 같은 결과를 내는 idempotent 동작으로 만든다. 백엔드 처리가 제한 시간을 초과하면 이미 처리된 결과만 포함한 report와 `incomplete=true`를 반환한다.

### 3.3 이벤트 계약

클라이언트 이벤트에 다음을 추가한다.

```json
{
  "event": "session.end",
  "timestamp_ms": 123456,
  "data": { "sessionId": "..." }
}
```

서버의 `session.completed`는 프론트가 직접 사용할 수 있는 최종 집계를 포함한다.

```json
{
  "type": "session.completed",
  "sessionId": "...",
  "timestamp": 123456,
  "report": {
    "transcript": "...",
    "gaze": {},
    "speech": {},
    "filler": {},
    "incomplete": false
  }
}
```

실시간 `feedback`은 자기 source의 데이터만 의미 있게 채운다. 없는 필드는 정상값으로 위조하지 않고 `null` 또는 생략한다. 프론트는 다음 상태를 독립적으로 관리한다.

- `latestGazeFeedback`
- `latestSpeechFeedback`
- `latestPronunciationFeedback`
- `transcript`
- `completionReport`

### 3.4 오디오와 Qwen3-ASR

브라우저에서 Web Audio API로 mono 입력을 받고 선형 보간으로 16 kHz로 다운샘플링한다. 별도 npm 패키지는 추가하지 않는다. 2초 단위 청크와 250 ms 중첩을 기본값으로 사용한다. 중첩 때문에 반복되는 문장은 기존 `appendTranscript`의 접두·접미 중복 제거로 합친다.

각 청크에는 다음 메타데이터를 함께 전달한다.

- 캡처 시작 타임스탬프
- 전체 청크 길이
- RMS 무음 비율 또는 실제 발화 구간 길이

발화 속도는 최종 transcript의 한글 음절 수를 실제 발화 구간 길이로 나누어 계산한다. 무음 청크는 STT 호출 전에 제외한다. 습관어는 `transcript.final`에서만 누적하여 partial/final 중복 집계를 막는다.

Qwen 로딩 또는 추론 실패는 명시적인 `SPEECH_AI_UNAVAILABLE` 오류로 표시한다. 사용자가 선택하지 않은 자동 Mock 전환은 제거한다. 개발용 텍스트 transcript 주입은 테스트 경로로만 유지한다.

### 3.5 시선 분석

시선 개선은 두 단계로 진행한다.

#### 단계 A: 판정 계약과 측정 기반 정리

먼저 모델과 무관한 출력 계약을 정의한다.

```text
face_detected: boolean
head_pose: { yaw, pitch, roll }
gaze_direction: center | left | right | up | down | unknown
attention_state: camera | screen | away | unknown
quality: 0..1
confidence: 0..1
calibrated: boolean
```

- 얼굴 미검출, 품질 부족, 보정 전 상태를 `away`와 구분한다.
- 집계는 실제 연속 샘플 타임스탬프 차이를 사용한다.
- 1~2프레임 흔들림은 경고하지 않고 시간 기반 hysteresis를 적용한다.
- 자연어 피드백은 위 판정값과 지속시간을 이용한 결정적 템플릿으로 만든다. LLM은 사용하지 않는다.

#### 단계 B: 어댑터 후보 평가 후 하나만 채택

Apple Silicon localhost 조건에서 다음 두 후보를 동일한 샘플로 비교한다.

- UniFace MobileGaze: ONNX/Apple Silicon 친화적이고 경량 배포에 유리하다.
- L2CS-Net: 공개된 정확도 근거가 더 많지만 ResNet 기반으로 상대적으로 무겁다.

평가 항목은 설치 가능성, 평균/P95 추론시간, 얼굴 미검출률, 정면/좌/우/상/하 분류 정확도다. 자동화된 fixture 영상과 사용자가 수행하는 약 3분 수동 캘리브레이션 테스트를 사용한다. 통과 기준을 만족하는 가장 가벼운 하나만 제품 어댑터로 남긴다. 둘 다 통과하지 못하면 기존 MediaPipe 기반 판정을 유지하되 `experimental`로 표시하고 수치를 과장하지 않는다.

### 3.6 자연어 시선 피드백

피드백은 단발성 프레임이 아니라 최근 시간 창을 기준으로 한다.

- 얼굴 미검출 1초 이상: `얼굴이 화면에서 벗어났습니다. 카메라 중앙으로 이동해 주세요.`
- 화면 주시 2초 이상: `화면을 오래 보고 있습니다. 답변할 때는 카메라를 잠시 바라보세요.`
- 좌/우 이탈 2초 이상: `시선이 오른쪽/왼쪽에 머물고 있습니다. 정면으로 천천히 돌아오세요.`
- 품질 부족: `조명이 어둡거나 얼굴이 너무 작아 시선을 판단하기 어렵습니다.`
- 안정 상태: 경고를 반복하지 않고 상태가 회복될 때 한 번만 알린다.

동일 메시지의 최소 재알림 간격을 두어 경고가 화면을 도배하지 않게 한다.

## 4. 오류 처리

- 마지막 오디오 전송 실패: 종료 report를 `incomplete=true`로 표시하고 사용자에게 재시도 가능한 안내를 보인다.
- STT 오류: 시선 처리는 계속하고 음성 모듈만 오류 상태로 둔다.
- 시선 오류: 음성 처리는 계속하고 시선 모듈만 오류 상태로 둔다.
- WebSocket 종료 중 연결 끊김: 이미 받은 transcript를 보존하되 최종 report가 아님을 표시한다.
- 시선 품질 부족: 틀린 방향을 추측하지 않고 `unknown`으로 반환한다.

## 5. 검증

### 5.1 자동 테스트

- `session.end`가 `ping`으로 변환되지 않는다.
- 마지막 오디오 flush가 완료된 뒤 종료 이벤트가 전송된다.
- 백엔드가 큐를 비운 뒤 정확히 한 번 `session.completed`를 보낸다.
- speech 이벤트가 gaze 상태를 바꾸지 않고 gaze 이벤트가 speech 상태를 바꾸지 않는다.
- 48 kHz 입력을 16 kHz mono로 변환했을 때 길이와 WAV 헤더가 정확하다.
- 중첩 transcript가 중복 없이 합쳐진다.
- partial transcript가 습관어 집계에 포함되지 않는다.
- 시선 이탈 시간이 실제 타임스탬프 간격으로 계산된다.
- 얼굴 미검출과 시선 이탈이 서로 다른 상태로 유지된다.

### 5.2 수동 통합 테스트

사용자 카메라·마이크 권한이 필요한 마지막 단계만 사용자가 수행한다.

1. 정면, 좌, 우, 상, 하를 각 10초 유지한다.
2. 정상 속도, 빠른 속도, 느린 속도로 동일 문장을 읽는다.
3. `음`, `어`, `그`를 의도적으로 포함한다.
4. 문장 중간에 세션을 종료해 마지막 단어가 transcript에 남는지 확인한다.

목표 기준:

- 마지막 음성 청크 누락 0회
- source 간 상태 덮어쓰기 0회
- 정면/이탈 이진 분류 F1 0.90 이상
- 5방향 분류 macro F1 0.80 이상
- 정면 상태의 잘못된 시선 경고 분당 1회 이하
- 시선 피드백 end-to-end P95 300 ms 이하
- 연속 실행 중 오디오·비디오 큐가 지속 증가하지 않음

## 6. 구현 순서와 경계

1. 세션 종료 이벤트와 완료 report 계약
2. 프론트 피드백 상태 source별 분리
3. 16 kHz 오디오 변환, 마지막 flush, Qwen 오류 가시화
4. 발화 속도·습관어·transcript 집계 정합성
5. 시선 출력 계약, 실제 시간 집계, 경고 안정화
6. UniFace/L2CS 벤치마크와 최종 어댑터 선택
7. 전체 자동 테스트와 사용자 수동 통합 테스트

각 단계는 테스트가 통과하는 독립 커밋으로 만든다. 기존 `codex/remove-style-add-transcript` 브랜치의 style transfer 제거와 받아쓰기 기능을 기반으로 새 구현 브랜치를 만든다.

## 7. 이번 범위에서 하지 않는 것

- 감정, 긴장, 당황을 확정적으로 분류하는 기능
- 얼굴 색 변화 기반 감정 추론
- Laya/Jev 기반 판정 결합
- LLM 기반 면접 질문 생성 및 자연어 피드백 생성
- 다중 사용자 스케줄링과 GPU 서버 최적화
- 원본 영상·음성 저장

후속 감정 분석에서는 이번에 분리한 `head_pose`, `attention_state`, `quality`, 발화 속도, pause, filler 등의 시계열을 `BehaviorWindow` 입력으로 재사용한다. 다만 감정은 관측값과 분리된 `affect_hypothesis`로 표현하고 사용자 개인 기준선과 별도 검증을 거친다.
