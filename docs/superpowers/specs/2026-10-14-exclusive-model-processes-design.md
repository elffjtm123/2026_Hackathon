# Qwen 9B 요약과 실시간 모델의 배타적 프로세스 설계

## 1. 목적과 승인 범위

현재 맥북(Apple M5, 메모리 16GiB)에서 Qwen3.5-9B Q4_K_M으로 발표 대본의 문장별 요약을 만든다. 요약 모델과 STT·시선 모델은 추론뿐 아니라 가중치의 메모리 상주도 겹치지 않게 한다. 사용자는 대화에서 별도 프로세스 실행 및 단계별 종료 구조를 승인했다. 이 문서는 그 구조의 구현 전 검토본이다.

작업 브랜치는 `codex/local-script-summary`이며 `main`은 변경하지 않는다. 기존 요약 버튼, 원문 문장 번호별 매핑, 직접 수정, 요약 표시 토글, 발표·면접의 미디어 계약과 최종 리포트를 유지한다. 이번 범위는 로컬 단일 사용자이며 다른 앱의 모델·프로세스는 종료하지 않는다.

## 2. 코드에서 확인한 변경 이유

- `app/main.py`는 서버 시작 시 STT·시선 모델을 부모 프로세스에 로드한다.
- `LocalQwenSpeechAdapter.close()`는 실행기를 닫지만 `self.stt`를 비우지 않는다.
- `UniFaceGazeAdapter.close()`는 종료 작업을 예약하며 실제 네이티브 자원 종료를 기다리지 않는다.
- 기존 요약은 별도 `llama-server` 프로세스를 종료·회수하지만, STT·시선의 상주 메모리는 그대로 남는다.
- 세션 진입 경로는 데모/인증 WebSocket v1·v2와 WebRTC이다. 현재 v2 데모는 registry를 거치지 않으므로 registry만 수정해서는 배타 실행을 보장할 수 없다.
- 진행 중 작업의 취소는 네이티브 추론의 종료를 의미하지 않는다. 프로세스 생성·회수 경합과 반복 취소를 처리해야 한다.

## 3. 채택 구조

### 책임 분리

부모 FastAPI는 인증, DB, 미디어 수신, 기존 bounded queue, VAD·발화 구간 분할, 대본 정렬, 집계 및 리포트만 담당한다. 부모에서는 STT·시선의 가중치를 만들거나 시작 시 모델을 워밍업하지 않는다.

기존 `llama-server`를 요약 전용 자식으로 사용한다. 별도의 실시간 자식 하나가 Qwen3-ASR와 MediaPipe Face Landmarker·MobileGaze를 소유한다. STT와 시선의 기존 알고리즘 및 각각의 독립 실행기는 자식 내부에서 재사용한다. 영상 때문에 음성 추론이 직렬화되지 않게 한다.

부모의 어댑터는 기존 `infer(MediaPayload) -> AIResult` 인터페이스를 유지하는 IPC 대리 객체로 바꾼다. 현재 외부 HTTP 어댑터는 전체 MediaPayload/AIResult를 전달하지 않으므로 이 로컬 IPC에 그대로 재사용하지 않는다. 새로운 외부 AI 서비스나 공개 포트는 만들지 않는다.

### 프로세스 간 통신

맥북 범위에서 표준 라이브러리의 비동기 Unix-domain socket을 사용한다. 실행마다 소유자 전용 임시 디렉터리와 소켓을 만들고 종료 후 제거한다. 자식은 `python -m ...`으로 새 인터프리터에서 실행하여 이미 로드된 모델을 fork로 복제하지 않는다.

요청은 길이 제한이 있는 JSON 메타데이터와 raw 미디어 바이트로 구성한다. 메타데이터에 요청 ID, 모듈, 세션 ID 및 기존 MediaPayload의 모든 시간·발화 구간 필드를 포함한다. 응답은 요청 ID와 기존 AIResult의 모든 필드를 포함한다. 미디어를 base64로 부풀리거나 pickle로 역직렬화하지 않는다.

메타데이터·payload·응답 길이, 모듈, 요청 ID, 응답 필드를 양쪽에서 검사한다. 모듈당 네이티브 추론 하나만 진행하며 취소된 요청도 실제 종료 전에는 해당 슬롯을 재사용하지 않는다. 부모의 기존 큐를 재사용하고 IPC에 무제한 추가 큐를 만들지 않는다. 원문 음성·영상·전사는 디스크나 로그에 기록하지 않는다.

## 4. 공유 수명주기와 경합 제어

단일 소유 관리자가 요약 자식과 실시간 자식의 생성·종료·세션 소유권을 관리한다. 요약 서비스와 모든 세션 진입 경로는 이 관리자에서 실행권을 얻는다. 기존의 서로 다른 busy 검사만으로 배타성을 구현하지 않는다.

| 상태 | 메모리에 로드될 수 있는 모델 | 허용 전이 |
|---|---|---|
| idle | 없음 | 요약 준비 또는 실시간 준비 |
| summary_starting / summarizing | 9B만 | 요약 종료 처리 |
| summary_stopping | 9B만, 종료 대기 | PID 회수 후 idle |
| realtime_starting / practicing | STT·시선만 | 세션 종료 처리 |
| realtime_stopping | STT·시선만, drain·종료 대기 | PID 회수 후 idle |

상태 변경과 실행권 확보는 첫 await 전에 일관되게 예약한다. 종료 대기 상태에서도 반대 종류 작업을 시작할 수 없다. 생성 도중 취소되더라도 실제 자식 핸들을 확보해 회수하며, 반복 취소로 정리가 취소되지 않게 한다.

실시간 세션 하나만 허용한다. 같은 세션의 기존 WebSocket·WebRTC 조합은 유지하되 다른 세션 시작은 명시적으로 거부한다. 시작 실패와 중복 종료도 소유권 및 프로세스 핸들을 남기지 않는다.

## 5. 사용자 흐름

1. 화면 진입: 웹 서버만 실행하고 무거운 모델은 로드하지 않는다.
2. 요약 시작: 실시간 실행권이 없음을 확인한 후 9B 자식을 실행한다. 문장별 요약은 기존 방식으로 생성하고, 내용 검토가 필요한 AI 초안으로 표시한다.
3. 요약 완료·실패·취소: 자식을 종료하고 PID 회수 및 소켓 정리를 확인한다. 완료 응답과 발표 시작 잠금 해제는 그 이후다.
4. 발표·면접 시작: 요약 자식이 없음을 확인하고 실시간 자식을 실행한다. 필수 모델 준비 확인 후에만 `session.ready`와 정면 보정을 진행한다.
5. 세션 종료: 마지막 오디오 및 이미 수락한 큐를 기존 제한 안에서 drain하고 집계한다. 실시간 자식의 종료·회수가 완료된 뒤에만 최종 완료를 알린다.
6. 연결 종료·오류: 미완료 결과를 명시하고 소유 자식을 정리한다. 다음 요청이 이전 프로세스를 덮어쓰지 않게 한다.

UI의 모델 준비 중 안내와 시작 잠금을 유지하고, cold start를 위한 제한 시간과 종료 대기 시간을 서버·프론트에서 맞춘다. 모델 로딩을 발표 시간이나 발화 시간에 포함하지 않는다. 요약 버튼, 문장별 편집, 토글의 위치는 바꾸지 않는다.

## 6. 오류와 상태 계약

- 서버 `/health/ready`의 DB·Redis 준비 상태와 모델의 실제 로드 상태를 구분한다. 모델 상태에 `idle`·`loading`을 추가하고 프론트 타입·표시도 함께 갱신한다. 미로드 모델을 `ready`로 표시하지 않는다.
- 필수 모델 로딩 실패는 `unavailable` 및 안전한 원인 코드로 반환한다. 실제 결과가 없으면 전사·시선·속도 값을 만들지 않는다. 다음 시도에서 새 자식으로 재시도할 수 있어야 한다.
- 요약 중 실시간 시작은 `SUMMARY_BUSY`, 실시간 중 요약은 `PRACTICE_ACTIVE`로 거부한다. 기존 HTTP 상태 및 WebSocket 오류 계약은 유지한다.
- worker 죽음·IPC 단절·잘못된 응답은 분석 오류와 미완료 리포트로 연결한다. 종료는 정상 종료 요청 후 5초를 기다리고, 필요하면 terminate/kill 후 반드시 wait로 회수한다.
- 전체 시작·종료 실패 시 부모 서비스는 계속 요청을 받을 수 있어야 한다. 부모가 종료되면 자식의 IPC 연결 종료도 감지하여 자식이 스스로 종료한다. 부모가 정상적으로 종료되는 경로에서는 관리자가 직접 회수를 책임진다.
- `ai_mode=http`에서는 모델의 메모리를 이 서비스가 소유하지 않으므로 배타 메모리 모드를 제공하지 않는다. 이 조합의 요약 요청은 명시적으로 거부하고 외부 서버까지 메모리를 해제했다고 표시하지 않는다.

## 8. 변경 영향과 검증 기준

대상은 `app/main.py`, AI worker·수명주기 관리자·IPC 대리 어댑터, 요약 서비스, pipeline·registry, 모든 세션 시작/종료 경로, health·모듈 상태 타입, 프론트 준비/종료 대기·모델 표시, 설정·문서와 관련 테스트다. 기존 VAD, 시선 판정, 발화 속도·습관어 계산, 대본 정렬 알고리즘을 바꾸지 않는다.

검증은 TDD로 다음을 포함한다.

- idle에서 가중치가 로드되지 않음, 요약 자식과 실시간 자식의 PID 생존 구간이 겹치지 않음.
- 두 종류 작업의 동시 요청, 모든 v1/v2·WebRTC 진입점, 시작 중 취소와 반복 취소, 세션 소유권·중복 종료.
- IPC가 MediaPayload와 AIResult의 정보를 잃지 않음, malformed·과대 입력·죽은 worker·늦은 응답 거부, 영상과 음성의 독립 실행.
- 마지막 음성 drain 및 리포트가 유지됨, 로딩 실패·worker 죽음·연결 종료 후 새 세션으로 복구 가능.
- 요약 원문 문장 매핑, 편집·토글·대본 변경 초기화, 오류 시 임의 결과가 없는 기존 동작 유지.
- 테스트용 자식은 테스트에만 두며 운영 코드에 fake provider·우회 설정을 추가하지 않음.
- 현재 맥북에서 실제 9B 요약 후 실제 STT·시선 worker 로딩·종료 순서를 기록하고, 부모/자식 RSS·시스템 메모리 압박·swap의 전후 관측을 함께 보고함.
- 기존 Python·프론트 전체 테스트, Ruff·mypy·ESLint·TypeScript 빌드 통과.

프로세스 종료는 해당 프로세스의 모델 소유 메모리를 해제하는 근거다. OS 파일 캐시·swap이 원래 수치로 즉시 돌아온다거나, 다른 앱을 포함한 전체 메모리 사용량이 일정하다고 보장하지 않는다. 실제 카메라·마이크의 정성 평가는 사용자 확인과 구분해 보고한다.

## 9. 이번 범위에서 제외

다중 사용자, 공개 배포, Windows IPC 대응, CPU 최적화, 모델 선택 메뉴, 모델 품질 개선, 다른 앱 종료, 원본 미디어 저장, main 병합·푸시는 포함하지 않는다. 모델을 매번 로드하는 시작 지연은 메모리 절약과 교환하는 명시적 비용이다.
